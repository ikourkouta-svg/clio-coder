## Decisions and seam costs

The proposed layout was simplified: eight route registrations live in
`server/app.ts`; common worker reply/deadline handling lives in `worker/serve.ts`;
the small worker entry files dispatch their own allowed methods. Separate
`routes-*`, `reads-methods`, `ops-methods`, and paths/version adapters were not
needed. Version metadata uses the explicitly permitted HTTP shim. Token capture
is separate from the runtime-neutral client module so server tests can import
the typed client without bringing browser globals into the server TS program.

The toolchain index transitively imports its own `extension.ts`, manifest, and
domain-loader type graph. This is the accepted seam cost described in sprint
section 3.1; the HTTP process does not import that graph. Test fixture code uses
the exported `installPinnedTool` facility through the same adapter. No existing
`tests/contracts` fabricated installer test was found at this HEAD, so the app
owns a new fixture over that exported seam.

`installDir`, `binaryPath`, the PATH candidate, and vendored path are projected
as-is for the authenticated loopback operator, as S1 directs. Download entry URLs
are checked against the selected registry before invoking the injected fetcher.
Production fetching follows upstream redirects as the canonical root installer
does; the root seam owns SHA-256 verification and installation. Node permission
mode remains S9.

Hono is pinned to **4.13.5**, already present in the root lockfile, so adding the
app does not upgrade the optional MCP SDK's existing transitive Hono resolution.
Other existing importers and package versions were preserved. Shared packages
used directly by the app appropriately lose their optional-only lockfile marker.
All direct app versions are in the sprint's pinned-version table.
