## Built

- Permission cards bind to the active tool's identity, title, kind, input, and locations. Only one-time allow/reject options are accepted. Repeated/conflicting/stale decisions cannot execute a tool twice. A mismatched tool request fails closed without presenting an approval.
- Pending permissions survive snapshot/reconnect. The default escalation is 45 seconds and the budget is 10 minutes. Expiry emits `permission.expired`, sends `session/cancel`, then releases the parked request as cancellation. ACP is launched with its existing `--permission-timeout 605000` flag so the app's cancellation precedes the child's ceiling. Short timers are injectable only through the test harness.
- Turn-specific cancellation respects the active turn identity, with exactly one terminal projection; an old cancel cannot affect a later turn.
- GET/PATCH safe settings, GET/POST session autonomy, targets and probes call the existing ACP extensions. Unknown setting keys are rejected before ACP. UTF-8 byte ceilings supplement request schemas. Response projections discard extra fields and preserve the target-list truncation marker.
- Labels and closed-session deletion go through ACP. Closed-session commands use a temporary initialized **unbound** peer, persisted in the same ownership file before initialize and counted against the same four-child cap. Loading the ledger would make deletion inadmissible. A workspace id is optional in the label/delete body so closed history rows can be addressed without a live snapshot; workspace membership is checked through the reads worker first. The client explicitly confirms deletion.
- All seven opted-in ACP event kinds, including evidence ready, use closed bounded payload projections and source sequence checks. The fleet strip and permission state are part of the shared revisioned snapshot.
- PATCH/DELETE share the route table's authentication, JSON validation, idempotency and OpenAPI rules. Session snapshot revision headers now appear in OpenAPI too.
- Pending client deltas are bounded by 4,096 entries and 8 MiB. The fleet strip retains 128 facts, permission history 32 cards, the server 16 closed session snapshots in addition to active sessions, and the browser 32 recently used revision buffers. Live/closed session content retains S3's text/timeline/turn bounds.

The proposed separate permissions service and fleet-strip service are kept with the ACP modules because they own peer-specific state; REST and React remain separate consumers of the shared contracts. The former S3 no-UI rejection behavior is replaced by the actual permission controls; its rejection test now submits an explicit reject decision.
